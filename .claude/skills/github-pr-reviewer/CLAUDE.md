# GitHub PR Reviewer - Claude 設定

このファイルは、GitHub ActionsでClaude Code を使用してPRレビューを行う際の設定と指示を定義します。

## レビュー基準

### コード品質
- **可読性**: 明確な変数名、適切なコメント、一貫したコーディングスタイル
- **保守性**: DRY原則、適切なモジュール化、低い結合度
- **設計パターン**: 適切なデザインパターンの使用、SOLID原則
- **ベストプラクティス**: 言語やフレームワーク固有のベストプラクティスへの準拠

### セキュリティ
- **OWASP Top 10**: 一般的な脆弱性のチェック
- **認証・認可**: 適切な認証と認可の実装
- **入力検証**: ユーザー入力の適切な検証とサニタイゼーション
- **機密情報**: ハードコードされたシークレット、APIキー、パスワードの検出
- **インジェクション攻撃**: SQL、XSS、CSRF対策の確認

### テスト
- **カバレッジ**: 新機能や変更に対する適切なテストの存在
- **テストケース**: ユニットテスト、統合テストの妥当性
- **エッジケース**: 境界値やエラーケースのテスト
- **テストの保守性**: テストコードの品質

### パフォーマンス
- **アルゴリズム効率**: 時間計算量、空間計算量の最適化
- **リソース使用**: メモリ、CPU使用量の効率性
- **データベース**: クエリの最適化、N+1問題の回避
- **スケーラビリティ**: 大規模データや高負荷への対応

## 重要度の分類

### Critical（致命的）
即座にシステムに不具合を起こす問題。マージ前に必ず修正が必要。

**例**:
- セキュリティ脆弱性（SQLインジェクション、XSS）
- ハードコードされたシークレット
- 致命的なロジックエラー
- データ損失の可能性

**アクション**: REQUEST_CHANGES（変更要求）

### Major（重要）
セキュリティリスクや重大なバグの可能性があり、優先的に修正すべき問題。

**例**:
- 不適切なエラーハンドリング
- テストが不十分
- パフォーマンス問題
- 設計上の重大な問題

**アクション**: Issue起票（priority:high）

### Minor（軽微）
改善の余地があるがすぐには影響しない問題。

**例**:
- コードの重複
- 長すぎる関数やメソッド
- 不十分なコメント
- 命名規則の不統一

**アクション**: Issue起票（priority:medium）

### Suggestion（提案）
ベストプラクティスや最適化の提案。

**例**:
- よりエレガントな実装方法
- パフォーマンス最適化の機会
- リファクタリングの提案

**アクション**: Issue起票（priority:low）

## レビューワークフロー

1. **PR情報の収集**
   - PRのタイトルと説明を確認
   - 変更されたファイルとdiffを分析
   - 既存のコメントやレビューを確認

2. **コード分析**
   - 各観点（品質/セキュリティ/テスト/パフォーマンス）から分析
   - 検出された問題を重要度別に分類

3. **スコアリング**
   - 各カテゴリーを10点満点で評価
   - Critical: -3点、Major: -2点、Minor: -1点、Suggestion: -0.5点

4. **アクションの決定**
   - Critical問題あり → REQUEST_CHANGES
   - Major/Minor問題あり → CONDITIONAL_APPROVE + Issue起票
   - 問題なし → APPROVE

5. **フィードバックの提供**
   - PR上に詳細なレビューコメントを投稿
   - 各問題をIssueとして起票（PR作成者にアサイン）
   - 適切なラベルを付与

## Issue作成ガイドライン

### タイトル形式
```
[絵文字] [SEVERITY] 問題の概要 (ファイル名)
```

**絵文字**:
- 🔧 code-quality
- 🔒 security
- 🧪 testing
- ⚡ performance

### 本文テンプレート
```markdown
## 概要
PR #[番号] のレビューで検出された改善点です。

**関連PR**: [PR URL]

## 詳細
**カテゴリー**: [category]
**重要度**: [severity]
**ファイル**: `[filename]`

### 問題
[問題の説明]

### 推奨される対応
[修正方法や改善案]

## チェックリスト
- [ ] 問題を確認
- [ ] 修正を実装
- [ ] テストを追加/更新
- [ ] ドキュメントを更新（必要に応じて）
```

### ラベル
- **重要度**: priority:high, priority:medium, priority:low
- **種類**: code-quality, security, testing, performance
- **その他**: technical-debt

## 出力形式

### レビューコメント

```markdown
## PR Review Summary

**Status**: [絵文字] [状態]

### Analysis Results

#### Code Quality: X/10
- ✅ Good: [良い点のリスト]
- ⚠️ Minor: [改善点のリスト]
- ❌ Critical: [致命的な問題のリスト]

#### Security: X/10
[同様の形式]

#### Testing: X/10
[同様の形式]

#### Performance: X/10
[同様の形式]

### Actions Taken
1. ✅ **Approved** / ⚠️ **Conditional Approve** / ❌ **Changes Requested**
2. 📋 Created **Issue #XXX**: "[タイトル]" (assigned to @username)
[追加のアクション]

### Summary
[総合的な評価と推奨事項]
```

## 除外パターン

以下のファイルや変更は自動レビューから除外します：

- `package-lock.json`, `yarn.lock`, `Gemfile.lock` などのロックファイル
- `node_modules/`, `vendor/` などの依存関係ディレクトリ
- 自動生成されたファイル（`.generated`, `.auto` など）
- バイナリファイル
- 大規模なデータファイル（1000行以上のJSON、CSVなど）

## 特記事項

- レビューはAIによる自動分析であり、最終的な判断は人間のレビュアーが行う必要があります
- 言語やフレームワーク固有の高度な分析には限界があります
- 複雑なビジネスロジックやドメイン知識が必要な判断は人間のレビューが必要です
