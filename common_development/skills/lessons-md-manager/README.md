# Lessons MD Manager

CLAUDE.mdの「Lessons Learned」セクションを管理する Claude Code スキルです。

**Version**: v1.0

---

## 背景

Boris Cherny氏のTip #3「CLAUDE.mdへの投資」を仕組み化したスキルです。
セッション中の修正・失敗・発見を構造的に蓄積し、同じミスの繰り返しを防止します。

> 「CLAUDE.mdは複利で効く」 - これだけは全プロジェクトに即導入すべき

---

## 機能

- **学びの自動抽出**: セッション中の修正・失敗・発見を会話履歴から抽出
- **構造的な蓄積**: カテゴリ分類・重複チェック付きでCLAUDE.mdに追記
- **レビュー・整理**: 既存ルールの重複排除・品質改善・カテゴリ再編を提案
- **PF非依存**: Android, iOS, Web, バックエンド等、あらゆるプロジェクトで使用可能

---

## インストール

### Claude Code での使用

1. このスキルをプロジェクトにコピー:
   ```bash
   cp -r lessons-md-manager /path/to/your-project/.claude/skills/
   ```

2. またはパーソナルスキルディレクトリにリンク:
   ```bash
   ln -s /path/to/lessons-md-manager ~/.claude/skills/lessons-md-manager
   ```

3. Claude Code を再起動（既に実行中の場合）

## 使い方

### 学びの追記（追加モード）

```
/lessons
```

セッション中の会話を振り返り、以下のような学びを自動抽出します:
- エラー修正で判明した原因と対策
- 最初のアプローチが失敗して切り替えた方法
- APIやライブラリの予想外の挙動
- プロジェクト固有の規約・パターン

抽出された学びは確認後、CLAUDE.mdの `## Lessons Learned` セクションに追記されます。

### ルールのレビュー・整理（レビューモード）

```
/lessons review
```

既存の Lessons Learned セクションを分析し、以下を提案します:
- 重複エントリの統合
- 矛盾の検出
- 品質改善（具体性不足の修正、肯定形への書き換え）
- カテゴリの再編

## 出力フォーマット

CLAUDE.mdに追記される形式:

```markdown
## Lessons Learned

### テスト
- `@JvmInline value class` はMockKでモック不可。実インスタンスを使うこと
- APIレスポンスのネスト型は別クラスのInner Classを参照するケースがある。型定義を必ず確認

### ビルド・環境
- JAVA_HOME未設定でGradleテストが失敗する。android-test-runnerスキルで自動設定される

### コード規約
- Mapper戻り値の型は実装を確認すること。List<T>とList<List<T>>を間違えやすい
```

## ルール記述の品質基準

このスキルは以下の品質基準に基づいてルールを生成します:

| 基準 | 説明 |
|------|------|
| 肯定形 | 「〜しないこと」→「〜を使うこと」 |
| 具体性 | コード例・クラス名・型名を含む |
| 理由付き | なぜそうすべきかを添える |
| 再現可能 | 他の人が読んですぐ実行できる粒度 |

## 対応カテゴリ

| カテゴリ | 内容 |
|---------|------|
| テスト | テストコード、Mock、アサーション、テストライブラリ |
| ビルド・環境 | Gradle、JAVA_HOME、依存関係、CI/CD |
| コード規約 | 型、命名、パッケージ構造、アーキテクチャパターン |
| アーキテクチャ | レイヤー構造、依存方向、設計パターン |
| API | APIレスポンス、ネスト型、シリアライズ |
| ツール | Claude Code、IDE、Git、外部ツール |

プロジェクトに応じてカテゴリは自動的に追加・調整されます。
