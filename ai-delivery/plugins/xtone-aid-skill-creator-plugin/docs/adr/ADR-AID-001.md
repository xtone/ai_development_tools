# ADR-AID-001: メタプラグイン修正時はドッグフードを必須とする（自己循環参照リスクの緩和）

- **ステータス**: accepted
- **決定日**: 2026-05-28
- **決定者**: 豊田
- **関連判断ポイント**: DP-AID-01 〜 DP-AID-05（本プラグイン固有 DP 全般）
- **関連スキル**: aid-skill-creator-plugin-guide §メタゆえの留意点
- **根拠成果物**: `delivery/dogfood/auth/findings.md`（Step 11 ドッグフード結果）

## コンテキスト

`xtone-aid-skill-creator-plugin` は「**プラグインを作るためのプラグイン**」（メタプラグイン）。本プラグインのスキル群が、新規 AIデリバリプラグイン（T-023〜T-045 Rollout）を起こす責任を持つ。

このメタ性ゆえに、以下のリスクがある：

1. **循環参照リスク**: 本プラグインを本プラグインで再生成すると、壊れた版で自身を再生成し、壊れた状態が固定化される
2. **自己検証の限界**: 本プラグインのスキル仕様（`plugin-scope.json` / `plugin-architecture.{md,json}` の出力フォーマット）の妥当性は、**他プラグインに当てて初めて顕在化する**（ユニットテストでは網羅できない）
3. **型の劣化**: Rollout 中盤以降に「本プラグインのフォーマットが Rollout プラグインの実態を表現しきれない」状態が静かに進む可能性

Step 11 のドッグフード（auth プラグインを本プラグインのフォーマットで後追い起稿）で、上記 2 のリスクが具体的に検出された（FINDING-01: 横断 Skill の kind 区別不能、FINDING-02: 独自 sample-input の表現不能、FINDING-03: DP 命名形式の混在）。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **(A) 修正前に他プラグイン（auth 等）のドッグフードを必ず通す** | 循環参照リスクと型の劣化を**修正コミット前**に検出可能。findings.md の蓄積で型の進化が追跡できる | 修正のたびにドッグフード成果物を更新する手間。レビューが重くなる |
| (B) 本プラグインの自己再生成を全面禁止 | シンプル・運用ミスがない | 本プラグインのバグ修正・拡張が困難になる（手動運用に縛られる） |
| (C) 何も規約化しない（ベストエフォート） | 軽量 | 循環参照事故が起きてから気付く（壊れた状態が固定化されるまで気付かない可能性） |

## 決定

**(A) 採用：本プラグインの修正時は、修正コミット前に「他プラグインのドッグフード（findings.md 含む）」を必ず通す。**

### 適用範囲

- `xtone-aid-skill-creator-plugin/` 配下のすべての変更（SKILL.md / agents / commands / hooks / docs）に適用
- 例外：
  - タイポ修正・コメント修正など**スキル仕様に影響しない**変更は除外
  - `delivery/dogfood/` 配下それ自体の更新は除外（再帰防止）

### 運用フロー

1. 本プラグインに変更を加える前に、最新の `delivery/dogfood/auth/findings.md` を確認
2. 修正後、**ドッグフード対象プラグイン**（既定: auth）に対して `plugin-scope.json` / `plugin-architecture.{md,json}` を**最新仕様で再生成**
3. 再生成結果が現行 auth プラグインと整合するか確認（`findings.md` を更新）
4. **新たなギャップが検出されたら、本 PR で対応するか別 PR とするかをコミット前に決める**
5. PR description に「ドッグフード結果へのリンク」を含める（`docs/dogfood/auth/findings.md`）

### ドッグフード対象の拡張

- MVP: auth プラグインのみ（Step 11 で確立）
- Rollout 5 プラグイン目 / 10 プラグイン目 / 23 プラグイン目（全 Rollout 完了時）に対象を追加
- 追加されたドッグフード対象は `delivery/dogfood/<plugin>/` に同じ構造で配置

### CI での軽い検証（将来）

- `validate-plugin.sh` の拡張で「`delivery/dogfood/*/findings.md` の存在確認」を warn_and_document で追加（オプション・要 ADR-AID 追加）
- 完全自動化はしない（findings.md の判断は人間が必要）

## 帰結

### 正の帰結

- **循環参照リスクが運用ルールで顕在化**: 修正の影響範囲が修正コミット前に見える
- **型の進化が追跡可能**: findings.md の差分が「本プラグインの仕様変更が他プラグインに与えた影響」のログになる
- **メタ層のテスト戦略が確立**: ユニットテストの代わりにドッグフードを使う、というメタプラグイン特有の検証パターンを明文化

### 負の帰結 / リスク

- **PR レビューが重くなる**: ドッグフード成果物の確認も必要に。緩和：ギャップが無ければ `findings.md` の冒頭サマリだけ更新すれば足る
- **ドッグフード対象が陳腐化する**: auth プラグインが変わったら本プラグインのドッグフード結果も古くなる。緩和：auth プラグイン側の重要変更時にも本 ADR の更新義務を負う（双方向ルール）
- **修正者が忘れる**: 緩和：PR テンプレに「ドッグフード再実行の確認」チェックを追加する（後段タスク）
