# 架空案件インプット: 「みんなの読書会」アプリ

> これは xtone-auth-plugin の通し検証用の **架空案件**（フィクション）。実在の案件ではない。
> `/req-collect`（auth-requirements-extraction スキル）に渡すクライアント要件説明テキストの想定。

## 案件概要

本好きが集まって読書記録を共有し、オンライン読書会を開く BtoC コミュニティアプリ「みんなの読書会」を新規開発したい。Web（SPA）とスマホアプリ（iOS/Android）の両方を提供する。一般ユーザーと、読書会を主催するホストユーザー、運営管理者がいる。

## 認証まわりの要望（ヒアリング結果）

- 会員登録・ログインは **メールアドレス + パスワード** を基本にしたい。
- 忙しい人向けに **メールのリンク（一時トークン）でログイン**できると嬉しい（パスワードレス）。
- **Google / Apple アカウントでのログイン**にも対応したい（特にスマホアプリ）。
- 後から「最初はメールで登録したけど Google も紐付けたい」みたいに **認証方式を追加**できるように。
- パスワードの **変更・リセット**、**メールアドレス変更**、**退会**は当然できるように。
- バックエンドは Rails。API は **JWT で認可**したい。Web もアプリも **ログイン状態を保持**したい。
- セキュリティについては、**運営管理者だけは強めの認証**にしたい気がするが、一般ユーザーにそこまで求めると離脱しそう。どうするのがいいか相談したい。
- 規制の厳しい業界ではない。docomo / dメニュー連携の予定はない。
- 想定ユーザー規模は初年度で数万人程度。

## 非機能・制約

- 開発チームは Firebase の利用経験あり。
- 将来的に別の認証基盤へ移れる余地は残しておきたい（ベンダーロックインは避けたい）。
