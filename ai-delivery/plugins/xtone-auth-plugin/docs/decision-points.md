# 認証モジュールの判断ポイント一覧（設計資料）

このファイルは xtone-auth-plugin が扱う **人間判断必須ポイント**の一覧（DoD [Design] の「判断ポイント一覧」）。正は判断ポイントカタログDB（DP-, data_source_id: `64248f5c-b2f5-4c90-8ccb-7f53692b59b2`）。各 DP の `undecided` 連携と `decision_record` 記録は warn_and_document（T-002）で扱う。

## DP-007 認証スタック選択

- **フェーズ**: 設計
- **選択肢**: Firebase Auth / Devise+OmniAuth / AWS Cognito / dAccount / NextAuth.js / Laravel Sanctum
- **判断軸**: セキュリティリスク / クライアント規制 / ユーザ規模 / コスト
- **誤判断リスク**: クライアント規制に不適合な選択で、後段フェーズでスタック交代を迫られる
- **適用条件**: 認証設計フェーズ、MVP の Firebase Auth との比較
- **MVP の既定推奨**: **Firebase Auth**（Xtone 標準化が進み過去実績最多）。T-004 本決定により **IaaS 差し替え可能な設計**（AuthAdapter 層）を必ず維持。比較表に最低 1 つの代替を含める。

## DP-008 MFA（多要素認証）要件の振り分け

- **フェーズ**: 設計
- **選択肢**: 全ユーザ必須 / 管理者のみ / オプトイン / 不要
- **判断軸**: セキュリティリスク / ユーザ体験 / クライアント規制
- **誤判断リスク**: MFA スキップでセキュリティインシデント、過度適用で UX 劣化
- **適用条件**: 認証設計、特に金融・医療・B2B 案件
- **既定推奨**: 置かない（案件のセキュリティ要件・規制で人間が決定）。決まるまで `undecided` に DP-008 を残す。

## DP-015 dAccount 要件・docomo 規約遵守チェックのタイミング

- **フェーズ**: 設計
- **選択肢**: 全面的に docomo 規約遵守 / コア部分のみ / 検収チームと事前協議 / docomo 認証以外は独自規約
- **判断軸**: クライアント規制 / セキュリティリスク / スケジュール
- **誤判断リスク**: docomo 規約の見落としで検収不合格→リリース不可、過度適用で開発コスト肥大
- **適用条件**: docomo 系案件、dメニュー系連携のとき **のみ**。非該当案件はスコープ外と明示。

## DP-28 退会済みアカウントの再登録ポリシー

- **フェーズ**: 設計
- **選択肢**: (A) 拒否（403）/ (B) 復活（同一 UID で再ログイン許可・データ復元）/ (C) 新規作成（別 UID で再登録）/ (D) クールダウン期間付き再登録（N 日経過後のみ同一 UID で新規作成可、旧データは復元しない）
- **判断軸**: セキュリティリスク / クライアント規制 / ユーザ体験 / 保守性
- **誤判断リスク**: (B) 復活を不用意に許すと退会後にメール再利用された第三者が旧データを引き継ぎなりすまし・プライバシー違反（GDPR 17 条 / 個人情報保護法 30 条）。逆に (A) 一辺倒では BtoC SaaS / コミュニティで復帰導線が無く LTV 損失。DP 化していないと実装者が暗黙裏に (A) を選び要件側意図と乖離する
- **適用条件**: 退会機能を持つ全認証案件。特に (1) 要配慮個人情報（医療・金融）、(2) GDPR / 個人情報保護法の削除請求が要件、(3) BtoC SaaS / コミュニティで再加入導線を明示設計する案件で必須判断。IaaS の UID 再利用は provider 仕様にも依存するため設計フェーズで決め `responsibility_split` に反映する
- **MVP の既定推奨**: **(A) 拒否（403）**。要配慮個人情報案件で安全側に倒れる。BtoC で復帰導線が必要なら (D) クールダウンへ人間判断で切替

## 運用

1. 設計時に上記 DP を案件条件へ当てはめ、決められないものは推奨だけ提示する。
2. 未決は各スキーマの `undecided`（`DP-XXX`）と `docs/pending-decisions.md` に残す。
3. 決定したら判断ポイントカタログDB に `decision_record`（decided_by / decided_at / rationale）を記録し、`docs/pending-decisions.md` から外す。
