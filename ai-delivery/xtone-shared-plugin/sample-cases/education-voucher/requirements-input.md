# 架空案件インプット: 「みらいの種」教育バウチャー管理プラットフォーム

> これは複数プラグイン横断検証用の **架空案件**（フィクション）。実在の団体・サービスではない。
> `/req-collect` 系の requirements-extraction スキルに渡すクライアント要件説明テキストの想定。

## 案件概要

NPO 法人「みらいの種」が、家計困難世帯の子ども（小学 4 年〜高校 3 年）向けに、塾・習い事の費用を負担する**教育バウチャー**を発行・管理するプラットフォームを構築する。

利用フロー:
1. 保護者がオンライン申請し、書類審査を経てバウチャー（電子クーポン）を受け取る
2. 提携教室（塾・習い事）でバウチャーを利用、利用後に教室が NPO に請求
3. 寄付者向けに使途報告と年次レポートを発行

Web のみ（PC・スマホブラウザ）。スマホアプリは出さない。**自治体・寄付者・教育委員会への説明責任**が要件の中核。

## 想定ユーザー

- **保護者会員**: 申請者。家計状況・世帯人数・対象児童の情報を入力
- **対象児童**: バウチャー利用者（実利用は教室側でカウント、UI は保護者経由）
- **提携教室**: 全国 200 拠点想定。バウチャー受領 → 月次請求
- **NPO 事務局**: 申請審査・教室管理・請求承認・寄付者報告
- **教育委員会・自治体担当**: ダッシュボード閲覧（個人特定不可な統計のみ）
- **寄付者**: 月次・年次の使途報告閲覧

## 機能まわりの要望（ヒアリング結果）

### 認証
- 保護者会員はメール + PW + SMS 認証（OTP）。**SMS 必須**（メールアドレスを持たない層が一定数いる）
- 提携教室はメール + PW
- NPO 事務局は社内 SSO（Google Workspace）+ MFA 必須
- 教育委員会・寄付者は閲覧専用アカウント（メール + PW）

### バウチャー申請・審査
- オンライン申請フォーム（家計状況・世帯構成・対象児童・希望教室）
- 必要書類アップロード（所得証明等）
- 事務局審査ワークフロー（受付 → 一次審査 → 二次審査 → 承認 / 却下）
- 不備時の差し戻しと再申請
- 申請ステータスを保護者に通知（メール + SMS）

### 管理画面
- 事務局向け: 申請一覧・審査キュー・教室管理・請求承認・寄付者報告
- 教室向け: バウチャー受領状況・利用者リスト・月次請求書発行
- 教育委員会向け: 統計ダッシュボード（個人特定不可、属性別利用状況・地域別など）
- **役割ベース権限（RBAC）**: 事務局内でも審査担当 / 経理 / 管理者で見える範囲を分ける

### 帳票・外部連携
- 月次請求書 PDF を教室向けに自動発行
- 寄付者向け使途報告 PDF（個人特定不可、統計とエピソード）を月次・年次で発行
- 年次レポート（事業報告書）の PDF 出力
- 会計 SaaS（マネーフォワード or freee 想定）への請求データ連携（CSV エクスポート最低限）

### 通知
- 申請受理・審査結果・差し戻し・バウチャー有効期限切れ → メール + SMS
- 教室向け: 新規バウチャー受領・請求締め日リマインド → メール
- 事務局向け: 申請キュー残数・差し戻し滞留 → メール + Slack

### 監査ログ
- 申請データの閲覧・編集・承認はすべて操作ログを残す
- 個人情報アクセスログは別 DB に保管、削除不可（**4 年保管**）
- 操作ログの監査画面（事務局管理者・教育委員会のみ閲覧可）

## 非機能・制約

- 個人情報保護法準拠。所得情報はマイナンバー級の厳格管理
- **児童の個人情報**は親の同意のもとで取り扱う（同意ログ必須）
- バックエンドは Rails で OK
- 想定規模: 申請者 1 万世帯 / 年、教室 200 拠点、寄付者 5,000 人
- 自治体予算・寄付金で運営。**運営継続性が最重要**（ベンダーロックインは強い嫌悪感）
- 国内サーバ限定。海外リージョン禁止

## 体制・スケジュール

- クライアント: NPO 事務局長 + システム担当 1 名 + 寄付者リレーション担当 1 名
- 開発: BE 2 / FE 2 / PM 1
- 目標: 12 ヶ月（パイロット地域 → 全国展開）
