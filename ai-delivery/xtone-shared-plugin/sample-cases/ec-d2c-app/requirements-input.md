# 架空案件インプット: 「サンセット.koto」アパレル D2C アプリ

> これは複数プラグイン横断検証用の **架空案件**（フィクション）。実在の案件・ブランドではない。
> `/req-collect` 系の requirements-extraction スキルに渡すクライアント要件説明テキストの想定。

## 案件概要

ユニセックスのアパレルブランド「サンセット.koto（ことコト）」を運営する D2C スタートアップ。これまで主要 EC モール 3 社に出店していたが、独自アプリと自社 EC を立ち上げ、**会員 → 購入 → コミュニティ参加 → リピート**まで一気通貫の顧客体験を作りたい。

スマホアプリ（iOS / Android）と Web の両方を提供する。ブランド世界観を維持するため、汎用 EC SaaS のテンプレ感は避けたい。

## 想定ユーザー

- **一般会員**: 18〜35 歳、ファッション・ライフスタイル感度が高い層。月数千〜数万円の購買力
- **コミュニティホスト**: 着こなし投稿でフォロワーの多いインフルエンサー会員。ブランドからギフトサンプリングを受け取る
- **運営スタッフ**: 商品マスタ・在庫・受注・コミュニティモデレーションを扱う

## 機能まわりの要望（ヒアリング結果）

### 認証
- **メール + パスワード**に加えて、**Google / Apple / LINE ログイン**を提供したい
- 退会時はコミュニティ投稿の扱いを「匿名化して残す」「全削除」から選べると嬉しい
- 運営スタッフは強めの認証（MFA）必須。一般会員は任意

### 商品・コンテンツ
- 商品マスタは S, M, L, XL × 色のバリエーション管理。プリオーダー（受注生産）も扱う
- 商品詳細にスタッフ私物のスタイリング写真とコメント（**商品紐付きコンテンツ**）を載せたい
- **特集記事**（季節ごとのルックブックなど）を商品にひも付けてレコメンド表示

### 検索・発見
- フリーワード検索、絞り込み（カテゴリ・サイズ・色・価格帯・在庫あり）
- 「お気に入りのスタッフがコーディネートに入れている商品」のような**人物軸の発見導線**
- 検索結果は在庫切れを後ろに回す（完全除外はしない）

### 決済
- クレジットカード（Stripe 想定）、Apple Pay / Google Pay、後払い（NP 後払いまたは Paidy）
- 海外発送は将来対応するが MVP では国内のみ
- 定期購入はやらない（D2C だが単品中心）

### 通知
- 受注確定 / 発送 / 配送中 / 配達完了 → メール + アプリ push
- セール開始 / 在庫復活 → 任意で push と LINE 通知（オプトイン）
- マーケ用一斉配信機能は最低限あれば良い（自前で凝らない）

### コミュニティ
- 購入商品をタグ付けして投稿、フィード閲覧、いいね、コメント
- **モデレーション**: NG ワード自動フィルタ + 通報 → 運営チェックフロー
- ホスト会員は限定タグやサンプリング応募権を持てる

### 分析
- DAU/MAU、回遊、コンバージョン、商品別売上、検索ワード、特集記事閲覧 → 売上連動
- BI は社内 SQL チームが見るので、**データウェアハウス（BigQuery 想定）への日次連携**ができれば良い
- 個人情報の取り扱いは厳格に分離

## 非機能・制約

- バックエンドは Rails 想定。決済・在庫まわりは特に堅く
- 想定規模: MVP リリース 1 年で会員 5 万人、月間注文 2 万件
- 個人情報保護法準拠。クレカ番号は自社 DB に保持しない（PCI DSS スコープ最小化）
- 国内クラウド（AWS 東京 or GCP 東京）。海外リージョンは使わない
- ベンダーロックインはなるべく避けたい（ただし決済は Stripe で良い）

## 体制・スケジュール

- クライアント側担当: マーケ責任者 1 名 + CS リーダー 1 名
- 開発: 受託で BE 2 / FE 2 / iOS / Android 各 1 / デザイン 1 / PM 1
- 目標: キックオフから 6 ヶ月で MVP リリース
