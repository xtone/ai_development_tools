# Business Communication Plugin

ビジネスコミュニケーション支援プラグイン - 上司への技術報告・相談を効率化

## 概要

このプラグインは、開発者が上司に技術的な報告や相談を行う際に必要な資料を、インタビュー形式で効率的に作成するためのスキル群を提供します。

## スキル一覧

### 1. feature-estimation-assistant（機能見積もり提案）

新機能開発の見積もり提案書を作成します。

**使用場面:**
- 新機能の開発見積もりを提出する
- 実装方針と工数の承認を得る
- プロジェクト計画のための見積もり

**収集する情報:**
- 機能名と概要
- 機能の目的・背景
- 要件詳細
- 技術的アプローチ
- 作業項目と工数見積もり
- リスク・懸念事項
- 依存関係

**出力:**
構造化された見積もり提案書（機能概要、技術アプローチ、工数表、リスク分析など）

---

### 2. fix-approach-assistant（修正対応の方針相談）

コード修正の方針について、複数のアプローチを比較検討し、上司の判断を仰ぐための資料を作成します。

**使用場面:**
- コードレビューでの指摘対応
- リファクタリングの方針決定
- 仕様変更に伴う修正の相談
- 複数の実装方法から最適解を選ぶ

**収集する情報:**
- 修正が必要な箇所
- 修正の背景・理由
- 現在のコードと問題点
- 修正アプローチ案（複数）
- 各案のメリット・デメリット
- 推奨案とその理由
- 影響範囲と工数

**出力:**
構造化された修正方針相談資料（現状分析、複数案の比較表、推奨案、影響範囲など）

---

### 3. bug-investigation-assistant（不具合調査報告）

不具合調査の進捗状況を整理し、今後の作業方針について判断を仰ぐための報告書を作成します。

**使用場面:**
- 不具合調査の進捗報告
- 原因が特定できず、次のアクションの判断を仰ぐ
- 調査工数が膨らみ、エスカレーションが必要
- 暫定対応か調査継続かの判断を仰ぐ

**収集する情報:**
- 不具合の症状
- 再現手順
- 発生環境
- これまでの調査内容
- 原因の仮説と検証結果
- 未調査項目
- 次のアクション候補
- 求める判断
- 対応期限・影響度

**出力:**
構造化された不具合調査報告書（症状、調査結果、原因仮説、次のアクション候補など）

## 使い方

### インストール

このプラグインは既にプロジェクトに含まれています。

### カスタムコマンドの実行

Claude Codeで以下のスラッシュコマンドを実行してスキルを起動します：

```bash
# 機能見積もり提案を作成
/estimate

# 修正対応の方針相談資料を作成
/fix-consult

# 不具合調査報告書を作成
/bug-report
```

### 会話の中で使用

スラッシュコマンドを使わず、会話の中で自然に依頼することもできます：

```
機能見積もりの提案書を作成したい
```

```
コード修正の方針について相談したい
```

```
不具合調査の報告書を作りたい
```

### 使用フロー

1. **スキルを起動:** 上記のコマンドでスキルを実行
2. **インタビューに回答:** アシスタントが質問するので、順番に回答
3. **資料を確認:** 生成された資料を確認
4. **必要に応じて修正:** 修正が必要な場合は指示
5. **上司に提出:** 完成した資料を上司に提出

## 各スキルの特徴

### インタビュー形式

すべてのスキルはインタビュー形式で情報を収集します。以下の特徴があります：

- **一度に一つの質問:** 回答しやすいように質問を分割
- **具体例を提供:** 回答の参考となる例を提示
- **フォローアップ質問:** 必要に応じて詳細を確認
- **柔軟な対応:** 前の質問に戻ることも可能

### 構造化された出力

生成される資料は以下の特徴を持ちます：

- **読みやすい形式:** マークダウン形式で構造化
- **意思決定しやすい:** 判断材料を明確に提示
- **具体的:** 抽象的ではなく具体的な情報
- **網羅的:** 必要な情報を漏れなく含む

## ベストプラクティス

### 見積もり提案時

- バッファを適切に設定（不確実性が高い場合は20-30%）
- 過去の類似機能を参考にする
- リスクを隠さず正直に報告

### 修正方針相談時

- 最低2つ、できれば3つのアプローチを検討
- 自分の推奨案とその理由を明確に
- トレードオフを正直に説明

### 不具合調査報告時

- 事実と推測を明確に区別
- 調査内容は詳細に記録
- 複数の仮説を持つ（一つに絞らない）
- 次のアクション候補を複数提示

## カスタマイズ

各スキルのSKILL.mdファイルを編集することで、以下のカスタマイズが可能です：

- 質問項目の追加・削除
- 出力形式の変更
- プロジェクト固有の用語への対応
- 社内フォーマットへの適合
