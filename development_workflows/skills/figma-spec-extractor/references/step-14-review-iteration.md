# Step 14: レビュー反復反映 詳細ガイド

Step 13 完了時点で 3 つのレビュー（coverage / data-model / components）に未解消項目が列挙されている。Step 14 では **質問ループで方針を確定し、確定方針を全関連ドキュメントへ反映** する。

## 適用条件

- ユーザーが「レビュー方針を確定したい」「ドキュメントを精度向上したい」と希望した場合
- `extension` モードでは推奨（既存実装との整合性を取るため）
- `new` モードでも有効（仕様確定の品質を上げる）

## 全体フロー

```
Step 14a: レビュー優先順位の決定
   ↓
Step 14b: 質問ループ（4 件単位）
   ├─ ラウンド 1: 必須・最優先項目
   ├─ ラウンド 2: 残る推奨項目
   ├─ ラウンド ...: オプション項目
   └─ ラウンド N: 「全 scope 外」一括処理または個別判断
   ↓
Step 14c: 確定方針の反映
   ├─ 該当レビューに解消マーク（取り消し線 + 「解消済み」）
   ├─ data-model.md / components.md 等のマスタを直接更新（親 Opus）
   ├─ pages/*.md / actors.md / use-cases.md を並列更新（Sonnet サブ）
   └─ サマリー件数を再集計
   ↓
Step 14d: 次のレビューへ進む or 終了
```

## Step 14a: レビュー優先順位の決定

3 つのレビューを以下の順序で処理する：

1. **データモデルレビュー**（最優先）: 後続コンポーネント設計に影響するため
2. **整合性レビュー**: scope 外確定が他レビューの解消条件になる
3. **コンポーネントレビュー**: データモデル・整合性の確定を受けて最後に処理

## Step 14b: 質問ループ

`AskUserQuestion` ツールを使い、未解消項目を **必須 → 推奨 → オプション** の順序で質問する。

### 質問の作り方

- **1 ラウンドで 4 件以内**（`AskUserQuestion` の質問数上限が 4 のため）
- **各質問に 2〜4 個の選択肢**（同上限）
- 選択肢は **「scope 外」「既存活用」「新規追加」** のような実行可能な決定
- 関連する複数レビュー項目は **1 件の質問に集約**（例: ON DELETE 挙動 6 件を「推奨デフォルト採用 / すべて RESTRICT / FK 制約なし」の 1 質問に集約）

### ループ継続条件

- 必須項目が全て解消するまで継続
- 推奨項目が全て解消するまで継続（ユーザーが「全 scope 外」一括処理を希望すれば打ち切り）
- オプション項目はユーザーに **「個別に詳細検討するか / 一括 scope 外で残置するか」** を聞く

### 質問テンプレート例

```
質問: #X.Y 必須: {{項目の概要}}。{{選択肢が必要な理由}}

選択肢:
  - {{方針 A}}: {{方針 A の詳細・影響}}
  - {{方針 B}}: {{方針 B の詳細・影響}}
  - {{方針 C}}: {{方針 C の詳細・影響}}
```

### Figma デザイン依存項目の扱い

「Figma 未定義／デザイン待ち」項目は **仕様確認では解決できない** ため、質問せずに「Figma 追加デザイン依頼中（デザイン待ち）」のラベルを付けて残置する。

## Step 14c: 確定方針の反映

### マスタドキュメントへの反映（親 Opus が直接編集）

| 確定領域 | 反映先 |
|---|---|
| データモデル方針 | `docs/data-model.md`（新カラム追加・運用ルール・FK ON DELETE 等） |
| コンポーネント方針 | `docs/components.md`（取り下げ・統合・新規追加・パラメータ追加） |
| 整合性方針 | `docs/reviews/coverage-review.md` の各項目に解消マーク |

### ページ・補助ドキュメントへの反映（並列 Sonnet サブエージェント）

`docs/pages/*.md` / `docs/actors.md` / `docs/use-cases.md` / `docs/pages/README.md` への反映は **ファイル単位で並列実行**：

```js
// 並列反映パターン
const agents = [
  Agent({ description: "pages/ 反映", model: "sonnet",
          prompt: "確定方針リスト + pages/ ファイル群を更新" }),
  Agent({ description: "actors/use-cases 反映", model: "sonnet",
          prompt: "確定方針リスト + actors.md / use-cases.md を更新" }),
];
```

各サブエージェントへのプロンプトには **「ID マッピング表（旧 → 新）」と「方針リスト」** を渡す。詳細は [`sub-agent-prompts.md`](sub-agent-prompts.md) の Step 14c テンプレート参照。

### レビューファイルの解消マーク

確定した項目は、レビューファイル内で以下のように更新：

```markdown
<!-- 解消前 -->
| 5 | 編集部からのメッセージカラム | ... | **必須** | ContestGroup に新規追加 |

<!-- 解消後 -->
| ~~5~~ | ~~編集部からのメッセージカラム~~ | ~~Contest に新規カラム追加で確定~~ | **解消済み** | – |
```

取り消し線（`~~...~~`）と「**解消済み**」ラベルで履歴を残す。

### サマリー件数の再集計

各レビューファイル末尾の「レビューサマリー」セクションを以下のスクリプトで再集計：

```bash
awk '/^\| [0-9~]+ \|/ {
  if (/\*\*必須\*\*/) hisu++
  else if (/\*\*推奨\*\*/) suii++
  else if (/オプション/) opt++
  else if (/解消済み/) kaisho++
}
END {print "必須:", hisu+0, "推奨:", suii+0, "オプション:", opt+0, "解消済み:", kaisho+0}' \
  docs/reviews/data-model-review.md
```

## Step 14d: 終了判定

- 次のレビュー（整合性 → コンポーネント）が残っていれば 14a に戻る
- 全レビューの未解消項目が「Figma デザイン待ち」「将来要件」のみになった時点で終了
- 終了時に最終サマリーを提示：

```markdown
## 仕様確認反復プロセス完了報告

| レビュー | 必須 | 推奨 | オプション | 解消済み |
|---|---|---|---|---|
| データモデル | X | 0 | Y | Z |
| 整合性 | X | 0 | 0 | Z |
| コンポーネント | X | 0 | 0 | Z |

未解消項目はすべて「Figma 追加デザイン依頼中」または「将来要件」です。
```

## 効果の目安（参考）

- 1 つのレビューにつき 4〜6 ラウンドの質問で大部分の項目が解消可能
- 質問あたり 1.5〜2 件のレビュー項目を集約（関連項目をまとめると効率化）
- 質問ループ後の未解消項目は「Figma デザイン待ち」または「将来要件」に集約される
