# 合成の手順（knowledge-synthesis v0）

週ごとに集まったナレッジカードを束ね、正（worked）と反（failed）の対立から合（提案）を出し、次の問いを決める。2026-W41 のカードで手作業で 1 回試した手順を、スキルの仕様として書き留めたもの。スキル（`SKILL.md`）はこの手順を実行し、決まった処理は `scripts/load_cards.py`（手順 1〜3 と指標）と `scripts/synth.py`（検査、まとめの生成、手順 8、合成テーマの変換）が受け持つ。根拠の強さ（人数・プロジェクト数・枚数）とテーマの問いはスクリプトが数える。

## 入力

- 対象の週（既定は前の週）。`knowledge-cards` の `cards.py week` と同じ ISO 週
- Notion「ナレッジカード」DB のうち、その週の行に紐づくカード全件
- `knowledge_sharing/questions.json`（問いの文と既定の極性）と `confidential_topics.json`

## 出力

| 出力 | 置き場所 | 内容 |
|---|---|---|
| 合成テーマ | Notion「合成テーマ」DB に 1 テーマ 1 行 | テーマ（結論の一文）、週、問い、カード、対立、合、採否 = 検討中 |
| まとめ | 週の行の配下の子ページ「まとめ」 | `templates/summary.md` の形 |
| 週の行 | 「週次 Tips」DB | ステータスを `合成済み` にする |

## 手順

### 1. カードを読み出す

query-data-sources（SQL）で、`週` に週の行のページ ID を含むカードを全件読む。relation 列はページ URL の JSON 配列なので、`LIKE` で絞り込める。

```json
{
  "data_source_urls": ["<cards の data source>"],
  "query": "SELECT url, \"カード\", \"問い\", \"プロジェクト\", \"極性\", \"確度\", \"タグ\", \"文脈\", \"根拠\", \"投稿者\", \"公開範囲\" FROM \"<cards の data source>\" WHERE \"週\" LIKE ? ORDER BY \"問い\"",
  "params": ["%<週の行のページ ID（ハイフン無し 32 桁）>%"]
}
```

100 件を超えるときは `ORDER BY url` と `url > ?` で区切って読む。読み出したら次を数えて控える: 投稿者の数、問いごとの枚数、極性ごとの枚数。

### 2. 重複を除く

同じ問い・同じプロジェクトで、claim がほぼ同じカード（`cards.py` の `normalize` が一致するもの）は 1 枚として扱い、代表に残りの URL を添える。別の人が同じことを書いたカードは重複ではない。束ねて「人数」を数える材料にする。

### 3. 事実カード（P1・P2・Q6）を表にする

事実カードはテーマに束ねない。まとめの「今週動いていたプロジェクト」に、プロジェクト・内容（claim のプロジェクト名より後ろ）・カードへのメンションを 1 行ずつ並べる。月次の合成でプロジェクトマップの材料にする。

### 4. 親和図を作る（意見カード）

意見カード（Q1〜Q5・Q7〜Q9）を、問いをまたいで意味の近いものに束ねる。

- 問いの極性は固定されている（Q1 は worked、Q2 は failed など）。そのため、同じ論点の正と反は別の問いに分かれて届く。問いごとに束ねると対立が見えなくなるので、**問いをまたいで束ねる**
- 束ねる軸は「何をしたか」ではなく「依頼やプロセスのどこが効いたか・欠けたか」。例: 「前提を書いたか」「完了条件を書いたか」「確認を先にしたか」
- テーマ名は結論の一文で書く（「〜について」にしない）
- 1 枚だけのテーマも残す。合成テーマ DB の `問い` には、束ねたカードのうち最も多い問いを入れる。同数ならカタログ順で先のもの
- 200 枚を超えるときは、先にタグとプロジェクトで粗く分けてから束ねる

### 5. 対立を書く

同じテーマに worked と failed が両方あれば、それを対立とする。claim が互いに矛盾する組（「短い依頼で通った」と「前提が足りず言い直した」など）も同じ。

- 書くのは**分かれ目**（`split`）の 1 文だけ。正と反のカードの claim は、スクリプトがカードから並べるので書き写さない
- 分かれ目の候補: タスクの種類（実装・調査・資料）、規模、フェーズ、問い返す手順（brainstorming など）を挟んだか、プロジェクトの性質
- 分かれ目はまとめで「分かれ目（推定）」として表示される。カードから言える範囲で書く

対立が無いテーマは「共通解」とし、`split` は空にする。

### 6. 合を書く

テーマごとに、次のどれかで提案を書く。

| 型 | 書き方 |
|---|---|
| 両立案 | 正と反の両方の利点を残すやり方 |
| 条件分け | 「〇〇のときは A、△△のときは B」 |
| 仕組み化 | スキル、hook、CLAUDE.md のテンプレ、プラグイン設定など、還元先を名指しする |

提案（`proposal`）は 1 文・80 字までで、何をするかを動詞で終える（「〜を最初に書く」「〜をコマンドにする」）。合には、次の 2 つを必ず添える。

- **根拠の強さ**: 何人・何プロジェクト・何枚のカードに基づくか（スクリプトが数える）
- **反証・限界**（`limits`）: この提案が当てはまらない場合や、カードから言えないこと。100 字まで

共有会で決める問い（`decision`）は、「〜しますか？」で終わる 60 字までの問いにする。

### 7. 次の問いを決める

合成で見えた未解決の点を、次の週の rotation の候補にする。既存の問い（Q3〜Q9）に当てはまればその ID を、当てはまらなければ新しい問いの文案を書く。questions.json に新しい問いを足すのは共有会で決めてから。

### 8. 機密の再確認

まとめと合成テーマの文面は、合成の段階で新しく書いた文章を含む。書き込む前に次の 2 つを通す。

- `scan_sensitive.py --tier internal`（knowledge-cards のスキャナ）で 0 件。カードへのメンション（`<mention-page url="..."/>`）は同じワークスペース内の参照で意図したものなので、タグを除いた本文にかける

```bash
sed -E 's#<mention-page url="[^"]*"/>#[card]#g' <まとめ.md> > <out>/.work/summary-scan.md
python3 -I <knowledge-cards>/scripts/scan_sensitive.py <out>/.work/summary-scan.md --vocab <sessions.json> --tier internal
```

  合成する人の手元に sessions.json が無ければ `--vocab` を省く（固定パターンだけで検査する）
- `confidential_topics.json` の語に当たらないこと（強い語・要確認の語とも）。当たったら、その文を消す。要確認の語は、カードに含まれていても自動では通さない。ユーザーが人事・経営の話ではないと確認した語だけ通す
- メンションを除くのは、今週のカードと作ったテーマのページへのメンションだけにする。それ以外のメンションは URL ごと検査する。行ごとと、改行をつないだ全文の両方を見る（語を改行や見えない文字で分けてもすり抜けないようにするため。コミット後のセキュリティレビューの指摘による）
- 判定は、書いたままの文字列と、Notion で表示される文字列（リンクは表示名だけにし、HTML タグ・エスケープ・強調記号を除いたもの）の両方に当てる。`取**締**役` や `経<span>営</span>会議` のように記法で語を分けても、表示どおりの語として止まる
- Notion に書く合成テーマの値（テーマ名・対立・合・本文）は、`to-notion` が `validate` と同じ判定を通してから出力する

### 9. 書き込む

1. 合成テーマ DB に create-pages で 1 テーマ 1 行を作る。`カード` にはカードのページ URL の配列、`週` には週の行の URL、`採否` は `検討中`
2. 週の行の配下に、create-pages（parent は週の行の page_id）で「まとめ」ページを作る
3. 週の行の `ステータス` を update-page で `合成済み` にする

合成テーマを作り直すときは、同じ週の既存の行を先に確認し、重複して作らない。

本文の書き方の注意（2026-W41 の書き込みで分かったこと）:

- `CLAUDE.md` や `SKILL.md` のようなファイル名は、Notion がドメイン名とみなして `http://CLAUDE.md` へのリンクにする。本文ではインラインコード（バッククォート）で囲む
- カードと合成テーマは `<mention-page url="..."/>` で参照する。表のセルにも置ける

## 機密の判定が守るもの（脅威モデル）

カードにしない話題の判定（`confidential_topics.json` と knowledge-cards の `topics.py`）は、**うっかりの漏洩**を防ぐためのもの。次の 3 つを想定している。

- 経営層のメンバーが、人事評価や経営の話題で Claude Code を使い、その記録がカードの材料に入る
- Claude がカードやまとめを下書きするとき、こうした話題の文を書いてしまう
- 提出後に Notion 上でカードが書き換えられ、合成の材料に入る

最後の歯止めは人の確認である。カードの提出も、合成の書き込みも、下書きを本人が確認してからでないと Notion に書かない（AskUserQuestion）。

**意図的に判定をすり抜ける書き方は、想定の外に置く。** 記号・空白・記法・見えない文字で語を分ける書き方（例: 取締役の間に記号を挟む）は、できるのが元の情報と Notion への書き込み権限をすでに持つ本人だけで、判定で防ぐ対象ではない。判定は、Notion で表示される文字列と、日本語の文字の間の区切りを詰めた文字列にも当てているので、ふつうの書き方の揺れでは止まる。ただし、すべての書き方を塞ぐことは目指さない。同じ種類の指摘（記法や区切りによる分割）は既知の限界として扱う。型の取り違えや、検査を通らない書き込み先など、別の種類の穴は直す。

## まとめの読ませ方（Progressive Disclosure）

読み手は、Web 制作会社のエンジニアが開発の進め方を議論するために読む。最初の 30 秒で「わかったこと」と「決めること」がつかめ、根拠は開いた人だけが読む構成にする。`synth.py render` がこの順に組み立てる。

| 層 | 見出し | 中身 |
|---|---|---|
| 1 | 今週わかったこと | テーマごとに、結論（`title`）と提案（`proposal`）の 2 行 |
| 2 | 共有会で決めること | テーマごとに、yes/no で答えられる問い（`decision`） |
| 3 | テーマの詳細 | 提案と根拠の強さ。正と反の例・分かれ目と限界はトグルの中 |
| 付録 | 次に聞くこと、今週動いていたプロジェクト（トグル）、数字で見る今週（トグル） | |

書き方の規則（UX ライティング）:

- 結論から書く。テーマ名は結論の一文（60 字まで）
- 1 項目 1 文。字数の上限（テーマ名 60、提案 80、分かれ目 80、限界 100、問い 60）を超えると `validate` が止める
- カードの言い換えをしない。例はスクリプトがカードの claim をそのまま並べる
- 社内の略語、内部 ID、セッション ID は書かない
- 合成テーマの「合」欄は提案の 1 文だけ、「対立」欄は「うまくいった n 件／うまくいかなかった n 件。分かれ目: …」になる

## 書かないこと

- 個人別の件数ランキングや、「誰が何を失敗した」の記述。代表カードの引用は claim とプロジェクトまでにし、投稿者名は出さない
- カードに無い事実。合で推定するときは推定と書く
- 人事評価・処遇や経営に関する話題（`confidential_topics.json`）

## 指標（まとめの冒頭に載せる）

| 指標 | 取り方 |
|---|---|
| 参加者数 | カードの投稿者の数 |
| カード枚数 | 問いごと・極性ごと |
| テーマ数・対立数・提案数 | この手順で作った数 |
| 確度 | observed / inferred の割合（Q2・Q4・Q5 は observed を増やしたい） |

## 試行の記録（2026-W41）

- 入力: 1 人・9 枚（P1 4、Q1 2、Q2 2、Q7 1）。パイロット前の試行
- 分かったこと
  - 問いごとに束ねると対立がまったく出なかった。Q1（worked）と Q2（failed）を同じ論点で束ねると、対立が 1 つ出た。この結果から、手順 4 を「問いをまたいで束ねる」にした
  - 1 人分だと、根拠の強さは「1 人」になる。合は仮説として書き、採否は共有会に回す
  - 合成テーマ DB の `問い` は単一選択なので、問いをまたぐテーマの扱いを決める必要があった（手順 4 の規則）
  - 機密スキャンは、カードへのメンションに含まれる Notion の URL を検出する。メンションのタグを除いた本文にかける（手順 8）
  - 書き込み先: 合成テーマ 3 行、週の行の配下の「まとめ（2026-W41）」ページ、週の行のステータス = 合成済み
- スキル v0 での dry-run（2026-10-13）: 手作業の合成のあと、もう 1 人分のカード 10 枚が W41 に届いていた（2 人・19 枚、意見 11 枚）。スキルで合成し直すと、テーマ 3・対立 2 になった（手作業では対立 1）。2 人目のカードで「対象と完成形を特定すると一度で通る」の正と反がそろったため。合成テーマの重複確認で、既存の 3 行を検出して書き込み前に止まることを確かめた
