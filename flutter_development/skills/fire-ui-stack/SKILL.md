# Fire UI Stack チームを作成

Fire UI Stackパターンに基づいて、UIの5つの状態を担当するTeam Agentチームを作成してください。

## Fire UI Stack とは

UIには5つの状態があり、それぞれの状態に対して適切なUIを提供することでユーザー体験を向上させます。

## 実行手順

以下の手順でTeam Agentチームを構成・実行してください。

### Step 1: チームを作成

`TeamCreate` ツールを使用してチームを作成:

```
TeamCreate:
  team_name: "fire-ui-stack"
  description: "Fire UI Stackパターンに基づくUI状態分析チーム"
  agent_type: "team-lead"
```

### Step 2: タスクを作成

`TaskCreate` ツールを使用して5つのタスクを作成してください。

**タスク1: Ideal State 分析**
- subject: "Ideal State（理想状態）のUI分析"
- description: "対象ファイルのIdeal State（データが正常に表示される理想状態）を分析。メインコンテンツの表示、レイアウト構造、正常系インタラクション、パフォーマンスを確認し、良い点と改善提案をレポートする。"

**タスク2: Blank State 分析**
- subject: "Blank State（空状態）のUI分析"
- description: "対象ファイルのBlank State（データがない空の状態）を分析。辞書データ未取得時の表示、テキストが空の場合のUI、ユーザーへの次のアクション導線を確認し、良い点と改善提案をレポートする。"

**タスク3: Loading State 分析**
- subject: "Loading State（読み込み中状態）のUI分析"
- description: "対象ファイルのLoading State（データ読み込み中の状態）を分析。ローディングインジケーター、スケルトンスクリーン、プログレス表示、タイムアウト処理の有無を確認し、良い点と改善提案をレポートする。"

**タスク4: Error State 分析**
- subject: "Error State（エラー状態）のUI分析"
- description: "対象ファイルのError State（エラーが発生した状態）を分析。ネットワーク/サーバー/認証エラー時の表示、エラーメッセージの分かりやすさ、リトライ機能の有無を確認し、良い点と改善提案をレポートする。"

**タスク5: Partial State 分析**
- subject: "Partial State（部分状態）のUI分析"
- description: "対象ファイルのPartial State（部分的にデータがある状態）を分析。一部データのみ表示時のUI、部分選択状態、オフライン時のキャッシュ表示を確認し、良い点と改善提案をレポートする。"

### Step 3: チームメイトを起動

`Task` ツールを使用して5つのチームメイトを**並列**で起動してください:

```
各チームメイトの共通設定:
  subagent_type: "general-purpose"
  team_name: "fire-ui-stack"
```

各チームメイトのプロンプトには以下を含めてください:
1. 担当するUI状態の説明
2. 対象ファイルのパス
3. 確認ポイント
4. 「TaskListでタスクを確認し、自分のタスクをclaimして作業完了後にSendMessageでリーダーに結果を報告すること」

### Step 4: 結果の統合

全チームメイトからの報告を受け取ったら、総合レポートを作成:

1. 各状態の分析結果をまとめる
2. 全状態の一貫性を確認
3. 優先度付きの改善提案リストを作成
4. 総合サマリーテーブルを出力

### Step 5: チームの終了

全タスク完了後:
1. 各チームメイトにshutdown_requestを送信
2. TeamDeleteでチームをクリーンアップ

## チームメイト定義

### 1. ideal-state-agent
- **名前**: ideal-state-agent
- **役割**: データが正常に表示される理想状態のUI分析
- **担当**:
  - メインコンテンツの表示
  - データが存在する場合のレイアウト
  - 正常系のインタラクション
- **確認ポイント**:
  - データが正しく表示されるか
  - レイアウトが崩れないか
  - パフォーマンスは問題ないか

### 2. blank-state-agent
- **名前**: blank-state-agent
- **役割**: データがない空の状態のUI分析
- **担当**:
  - 初回起動時の表示
  - データ未取得時のフォールバック
  - データが空の場合のUI
- **確認ポイント**:
  - ユーザーに次のアクションを促せているか
  - 空の理由が明確か
  - フォールバック表示は適切か

### 3. loading-state-agent
- **名前**: loading-state-agent
- **役割**: データ読み込み中の状態のUI分析
- **担当**:
  - ローディングインジケーター
  - スケルトンスクリーン
  - プログレス表示
- **確認ポイント**:
  - ユーザーに待機中であることが伝わるか
  - Shimmer/Skeleton効果は適切か
  - タイムアウト処理はあるか

### 4. error-state-agent
- **名前**: error-state-agent
- **役割**: エラーが発生した状態のUI分析
- **担当**:
  - ネットワークエラー
  - サーバーエラー
  - 認証エラー
  - バリデーションエラー
- **確認ポイント**:
  - エラーメッセージは分かりやすいか
  - リトライ機能はあるか
  - ヘルプへの導線はあるか

### 5. partial-state-agent
- **名前**: partial-state-agent
- **役割**: 部分的にデータがある状態のUI分析
- **担当**:
  - 一部データのみ読み込み完了
  - 部分選択状態
  - オフライン時のキャッシュ表示
- **確認ポイント**:
  - 追加データの読み込み導線があるか
  - 表示済みデータと未表示の区別がつくか
  - オフライン時の挙動は適切か

$ARGUMENTS

```
- ...

### 確認事項
- [ ] チェック項目1
- [ ] チェック項目2

```

```
|------|---------|-------------|

### 各状態の詳細

3. ...
```
